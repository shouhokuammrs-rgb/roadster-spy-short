- C15（本人指摘）：ロケットが車に当たっていた。車の浮上が 2.0 秒開始で、ロケットは 2.0 秒に既に車の尻に届いていた。**追い抜きの間ずっと浮いている必要がある**ので、噴射 1.6 秒・2.2 秒で底 2.2m、ロケット 14m/s は 1.25 秒発射に。0.1 秒刻みで「真下にいる間の隙間」を数値で確認（最小 1.36m）。**物理の嘘は目視より先に数値で潰す**（スクリプトで t ごとの位置を出す）
- C03（本人指摘）：カメラが Sho より先に上を向いていた。姿勢（pose）がキー間で補間されず、次のキーの時刻でパッと切り替わっていたのが原因（Sho は 1.2 秒に瞬間で上、カメラは 1.0 秒から動く）。**姿勢もキー間で補間する**ようレンダラとエディタを直し、Sho 0.8→1.3 秒、カメラ 1.0→2.0 秒（0.2 秒遅れ）、戻りも Sho 2.2→2.7、カメラ 2.5→3.2 に。副作用で C12 の「銃を下ろす→見上げる」も滑らかになった。**人が先、カメラが後**（カメラは視線を追う側）
- 人と車の粒度（本人提案）：参考動画のプリビズに合わせ、人を関節つき（肩・肘が姿勢で動く）、車をボンネット＋車体＋キャビンのシルエットに。C13a の「窓から乗り出して構える」が腕で読めるようになった。基準は **「動きが読めるか」**。質感・顔・細部は付けない（参照は配置と動き、外観はエレメント）
- 人物の粒度（本人指摘 2 回目）：箱に関節を足しただけでは「カクカク」のまま。参考動画を **調べてから** 作るべきだった（Higgsfield の Scene Builder はマネキンと円柱の車を置く）。結論は見た目より **骨格で動くこと**。骨格つきマネキンにして、座る・運転する・腰だめ・見上げるが体で読めるようになった
- 骨格に替えたら、座高が実車に合わないことが数値で出た（座った頭頂 1.14m に対しロードスターの屋根 1.2m）。乗員の位置を下げ、シートも床近くへ。**体格を固定すると、車・家具の寸法の嘘が見つかる**
- C02（本人指摘）：「残り 3 発」がどこにも描かれていなかった。台詞頼みで、ブロッキングには Vance も銃もいなかった。**設定は画面に物として置く**。窓越しに手元へ寄り、マガジンを抜いて弾 3 発（細部はプロンプト）。窓越しの寄りは、ドアの上端より手が下だと隠れる → カメラを上げて見下ろす。寄る途中で壁しか映らない瞬間があった → 中間キーで被写体を画面に残す
- C07（本人指摘）：座った Sho を塊ごと 65cm 横滑り＋60° 回転させていた。**座っている人は腰を動かさず、背骨・首・頭のひねりで振り向く**。ボーンの回転にひねり・横傾きを書けるようにして「turnright」を足した
- 主役 2 人のマネキンが銀のクーペと同じグレーで沈んだ → 肌色寄りのベージュに。**参照の中で物同士の色が被らないようにする**
- エディタのカメラ（本人指摘）：ズーム・寄りをやるには、ギズモで位置を動かし、レンズを数値で打ち、キーを手で押す必要があった。**カメラ視点のまま画面上で直接いじれて、離せばキーが入る**形にした。レンズもキーで動くようにして、C07 の「Sho の顔、大きく」を 20→55mm の寄りで実現した
- C01 と C06b（本人指摘）：同じ到着の瞬間なのに、C06b は崖の下から上がり、C01 は真上 10m から垂直に降りていた。先出しのカット（C01）を後のカットと別に作ったのが原因。**同じ出来事は 1 本のトラックにして、カットはそれを時刻ずらしで切り取る**。確認は「同じ出来事時刻のコマを並べる」（C06b t=3.2 と C01 t=2.4 が同じ頂点を見ているか）。ついでに C06b にも包囲（SUV 4 台・8 人）を入れた：同じ時刻なら同じ物がそこにいる
- エディタの自動保存が、公開した更新をその端末で上書きして隠していた（全体を保存して優先していた）。**本人の編集とこちらの更新がぶつかる箇所は、版の印で見分ける**
- 世界モデル（10/18、本人提案）：カットごとに動きを作っていたので、並べるたびに連続性の穴が見つかっていた（C01/C06b、C06b に敵がいない、上の道で車が前後に行き来）。**1 本の世界を動かして、カットはカメラで切り取る**に変えた。並べてみると上の道の追跡は、カットの合計時間に対して道が 150m 足りなかった。**速さを先に決めると、距離と配置が決まる**
- 映していない間を決めると物語の穴が見える：Sho がどこから車に乗るか、Vance がいつ乗り移るか、追っ手がなぜ上の道にいるか。どれも台本では決めていなかった
- 移行中に 2 つバグを見つけた：① 色の行に `#` コメントを途中に挿して、敵まで主役のベージュになっていた（**1 行の sed で式を壊さない**）② 車の部品名がすべて `car_…` で、複数台あると Blender がリネームし、主観カットのガラスが消えずにカメラが箱の中に入った（**部品名は物の id から作る**）
- 煙幕（本人指摘）：後ろ側（y<0）にしか広げておらず、前の SUV の 4 人からは乗り移りが丸見えだった。C09 が後ろの男の主観なので、そちら側だけ作っていた。**世界モデルでも、カメラに映る側だけ作る癖が残る**。煙は車を中心に前後へ広げ、真上からの図（tests/previs/smoke_topview.png）で両側の 8 人が隠れることを確認
- 時系列と撮りたい絵（本人指摘）：上の道の追跡を物理だけで決めたら、C13a の火花・C14 のアクセル・C15 の構図・C17 のカメラ位置・C18 の火球が撮れていなかった（C18 は火球が画面外）。**世界を 1 本にしても、物理の値は「撮りたい絵が成立する値」に寄せる**。確認は目視でなく、カメラに写る物の位置・大きさを 0.5 秒ごとに数値で出してビートと突き合わせる（previs/audit_cut.py）
- スマホ表示（本人依頼）：ページに viewport の指定が無く、スマホのブラウザが幅 980px の PC 画面として描いていたので、スマホ用の CSS が効いていなかった。もう一つ、カメラ視点の枠が縦長の画面で 9:16 になっていなかった（高さいっぱいに描いていた）。**縦長の画面で確かめるまで気づかない**。以後、エディタを変えたら PC（1280×820）とスマホ（390×844）の両方でスクリーンショットを撮る
- 着地後の横回転（本人指摘）：空中ロールの終わりを 360°、着地後のドリフトを 0° で書いたので、補間で着地後にもう一回転していた。**角度のキーは「同じ向き」でも数値が飛ぶと補間で回る**（360→0、−180→180）。回転を足すキーは、その後のキーも同じ値の系列で書き続ける。確認は 0.2 秒ごとの角度表を出す
- 直す途中、sed で行の途中にコメントを挿して式を壊した（10/18 に一度反省したのと同じ）。**コードの 1 行置換は Python の置換＋ py_compile で検証する**。sed で式の行にコメントを足さない

- 尺の判断（本人「長い気がする」）：前の IN/OUT はビートを見て手で決めていた。測ると、手で決めた値は動きのカットではほぼ規則どおりだったが、**台詞のカットは声を当てずに決めたので足りていなかった**（C03 は台詞 4.1 秒に 2.7 秒）。グレーボックスの通しは声がなく、人も止まっているので、台詞のカットほど「長く」見える。**長さの判断は声を当ててから**。仮の声（OpenJTalk）で十分に測れる
