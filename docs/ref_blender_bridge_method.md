# 参考 2：Blender プリビズ → 参照写真 → Seedance 2.5（YouTube: vLMw3hujMGs）

本人が 10/17 に共有した動画（文字起こしから要点を抽出。原文はチャットに）。
kaye.creatives（docs/ref_kaye_transcript.txt）が「Blender は高速カメラの救済」だったのに対し、こちらは **プリビズを主役にして、動画生成を最後の 1 回にする** やり方。

## 方法の骨子

1. **学習材料を先に渡す**：Higgsfield 公式の事例まとめ（Blender の作り方、参照 3 枚、Seedance プロンプトの組み合わせ）を LLM に読ませてから始める
2. **タスクを 3 つに分け、役割を混ぜない**（ここが一番大事、と本人も強調）
   | 素材 | 担う情報 |
   |---|---|
   | プリビズ動画（Blender） | カメラの移動、空間配置、通過順序、タイミング、人物のサイズ |
   | 参照写真（エレメント） | 顔、小道具、背景の外観 **のみ** |
   | Seedance 2.5 のプロンプト | 体重移動、関節の動き、視線、手の接触、着地の反応 |
3. **プリビズは何度でも直す（クレジット 0）**。生成前に「ガクつき」「カメラが止まる」「構図が参照と違う」を全部潰す。生成後に直すより、プリビズを作り直す方が速い
4. **LLM に自己分析させる**：「自分で分析して、完璧に合ったら報告して」と任せる。細部の修正依頼を人間が書き続けなくていい
5. **問題は人間が言語化する**：どうしても合わない箇所（例：横から銃を出して撃つ）は、何がズレているかを文章で特定して渡す。ここは機械に任せられない
6. **長いアクションは 3 分割**：25 秒・20 カットの追跡シーンは 1 回で生成できない。区切りのいい 3 本に分け、1 本ずつ「スキル読込 → 写真参照 → プリビズ添付 → 生成」
7. **理想が 1 回出たらスキル化**：以降は写真とプリビズを添付するだけで同じ品質が出るようにする
8. 時間感覚：プリビズ生成から動画完成まで 38 分（深夜 2:00 → 2:38）。480p で回してコストを抑える

## 接続（本人 PC 側の話。この環境では不要）

## 今回のリポジトリへの取り込み（10/17 決定）

- **3 役分担を prompts/ の型にする**：参照動画に任せることをプロンプトに書かない。プロンプトは「体の動き・視線・接触・反応」と連続性だけ（docs/03_prompting.md）
- **自己分析ループを工程に入れる**：レンダー → コマ割りを Claude が自分で読む → 直す → 本人には「合った」と判断してから見せる（docs/02_workflow.md）。今日の全カットレビューはこの形で回した
- **分割**：すでに 1 カット＝1 生成（5 秒）なので、分割の問題は起きない。代わりに「前のカットの終わり＝次の始まり」を守る
- **スキル化**：CLAUDE.md とこの docs がスキル。1 カットが通ったら prompts/ に「通った版」だけ残す
- Bridge は使わない：この環境の `pip install bpy` が同じ役割（previs/README.md）。本人 PC で Blender を開いて見たいときだけ `.blend` を渡す
