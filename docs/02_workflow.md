# 02 全体ワークフロー — フェーズと手順

参考にした手法：kaye.creatives「Red Bull 偽CM」の 4 ステップ（docs/ref_kaye_transcript.txt）
**アセット → 動画生成 → Blender リファレンス → マッチカット → 編集**。
これを忠実になぞりつつ、今回の検証で分かった「粒度」を各フェーズの中に足した。

---

## 全体像

```
P0 企画・台本・絵コンテ ──► P1 アセット ──► P2 カット生成 ──► P3 音 ──► P4 編集 ──► 公開
                                   ▲              │
                                   └── P2.5 グレーボックス（物理・カメラが難しいカットだけ前工程として挟む）
```

原則：**金のかかる工程（P2）に入る前に、金のかからない工程（P0・P2.5）で決め切る。**

---

## P0 企画・台本・絵コンテ（クレジット 0）

1. コンセプト 1 行：「ロードスターの技術を、スパイ映画の文法で見せる」
2. 視聴維持の設計：0–3秒フック／7–10秒ごとの再フック／クライマックスは終盤15秒前／無音 2 箇所（docs/01_story.md）
3. 伝えるべき設定を番号付きで列挙（設定1〜14）。**全カットにどの設定を伝えるかを割り当てる**
4. 二重の筋（Vance が追い詰められる／Sho が迎えに行く）を時間軸で噛み合わせる
5. カット割り：1カット＝1生成。カットごとに「視点（誰の目か）」を決め、同じ視点を連続させない
6. 台詞は最小。Vance は寡黙（眉だけ）、Sho は軽口
7. HTML Canvas でアニマティック（54秒）を作り、全体の流れ・テンポ・設定の伝わり方を確認。ベテラン監督視点でレビューして直す
8. 参考映画の撮り方を調べて反映（撃つ側は正対／飛翔は真横／着弾は手前ヒーロー・奥爆発…）

成果物：animatic/roadster-animatic.html、docs/01_story.md

## P1 アセット（Seedream 5.0 lite、1枚 1 クレジット）

1. キャラクター：Claude で「キャラクターシート」プロンプトを作る → 生成 → 気に入った 1 枚を **エレメント登録**（@Sho @Vance）
2. 車：実物を公式ギャラリーで観察 → **言葉に落として**（比率→面→ツートン→ガラス→ドア→ホイール→前→後ろ）→ 4面モデルシートを生成 → エレメント登録（@RoadsterW4 @VanceGT）
   - 比率は冒頭に、「roof only slightly higher than the wheels」のように数値的に書く
   - 公式写真はアップロードしない（利用規約）。見て、言葉にする
3. 場所：地形の条件（崖は垂直・上に道・海は右・夕方）を書いてロケーション登録（@CliffRoadDay @HarborCafe）
   - 光学ブロック（anamorphic / grain / grade）を末尾に付けると映画的になる。ただし **余計な光の筋**が出ることがある → 作り直し候補
4. 車内（コクピット）エレメントも作る予定。最初に通った車内カット 1 フレームを登録する

成果物：docs/04_assets.md

## P2 カット生成（Seedance 2.5、720p/9:16/5秒 = 35 クレジット）

### 1 カットの手順

1. **前後のカットとの連続性を確認**する（直前に何をしていたか、何が残っているか）
2. **画面内の全要素を列挙**し、名前を付ける（男 A〜D、CAR、CAMERA、VAPOR…）
3. **タイムライン方式で書く**：5秒を 3〜4 区間に切り、各区間で各要素の「始点の姿勢→終点の姿勢」を書く
4. DO NOT に「動作として」禁止したいことを書く（カメラ目線、停止、画面から出る…）
5. エレメントを `@` で挿入（候補が正しく選ばれたか **送信前に確認**）
6. 低コスト設定で生成（720p／標準）。1 カット 2〜3 テイクを見込む
7. **コマ割り（0.5秒ごと）を作って確認**する。「なんとなく良い」で通さない。動いているか／止まっているか／視線はどこか／連続性は合っているか
8. 直すのは「動作」。カメラとおおまかな動きが合っていれば、プロンプトは変えずに**もう 1 回同じものを回す**（部分的に良いテイクを編集で繋ぐ）
9. 通ったらプロンプトを prompts/ に保存し、所見を tests/ に残す

詳細：docs/03_prompting.md

### 生成の順番（失敗しにくい順）

| 順 | カット | 理由 |
|---|---|---|
| 1 | C03・C12・C14b | 車の動きなし／単純。エレメントの安定度を測る |
| 2 | C09・C13a・C13b | 車は写るが動きが単純 |
| 3 | C10・C14・C16・C18 | 車内ツーショット。顔の一貫性をここで詰める |
| 4 | C02・C07 | カメラ移動＋ドア開閉 |
| 5 | C01・C06・C06b・C11 | 垂直移動・落下・壁登り → P2.5 を挟む |
| 6 | C15・C17 | ジャンプ・ロール・着地・ロケット → P2.5 を挟む |

## P2.5 グレーボックス（Blender、クレジット 0）

参考動画では「AI が高速カメラの軌道を出せない」ときの救済策だったが、今回の検証で **配置と動きの"嘘"を潰す工程**としても効くと分かった（C12：敵が一列・丸腰／車が下がる、など）。

1. シーンを座標で定義する（道路=+Y、壁=x−4、ガードレール=x+3…）。車・人・カメラの位置を数値で置く
2. 動きをタイムラインで keyframe（誰が何秒にどこへ）
3. レンダー（Workbench、540×960、5秒で約 1 分）。コマ割りで確認し、数値を直して再レンダー
4. 上から見た「配置マップ」も出して、人に説明できる形にする
5. OK になったら、その動画を Seedance の **動画リファレンス**に入れ、見た目はエレメントで付ける。プロンプトは「リファレンスのカメラと動きをそのまま」と短くする

成果物：previs/c12_previs.py、previs/*.png

## P3 音

1. 声：ElevenLabs で 3 声（Vance＝低く乾いた声／Sho＝軽い声／Chief＝平坦）。台詞は日本語、字幕は英語
2. SE：スラスターは「プシュッ」＋轟音、壁走りは「ギュッ」とファンの唸り、着弾、着地「ドン」、遠い「バァン」
3. 音楽：Suno でスパイ調オリジナル。無音 2 箇所（19–22秒、36–43秒）。既存曲は使わない
4. Seedance が生成した音声は捨てる（口の動きだけ使う）

## P4 編集（Premiere / CapCut）

1. 5秒クリップを 2〜4 秒に切る。スローは編集でかける（C15 は 0.3倍→真下通過だけ 0.15倍）
2. 無音の設計を守る。黒で終わる（説明しない）
3. ロゴ・実名・既存曲は入れない

## 参考動画との差分（意識して変えた点）

| 参考動画 | 今回 |
|---|---|
| Claude にプロンプトを書かせ、そのまま生成 | 生成前に **アニマティックで全体を確認**し、カットごとに連続性・全要素・タイムラインまで書く |
| 気に入らなければ再生成 | コマ割りで「何が間違っているか」を特定してから直す。動作が合っていればプロンプトは触らず再生成 |
| Blender は高速カメラの救済 | Blender は **配置・動きの設計**にも使う（P2.5） |
| 1 枚のキャラシートで一貫性 | 同じ。＋車は実物を言葉に落として 4 面シート |
